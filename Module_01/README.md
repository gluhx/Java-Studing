## Vim: редактирование как язык действий

Vim запускается в normal mode. Нажмите i, введите текст, Esc, затем :w для сохранения и :q для выхода. :wq делает оба действия, :q! отбрасывает несохранённые изменения. Движения h j k l соответствуют влево, вниз, вверх, вправо; w переходит к следующему слову, 0 к началу строки, $ к концу, gg к началу файла, G к концу.

Оператор действует на движение: dw удаляет до следующего слова, ciw заменяет слово, yy копирует строку, p вставляет, u отменяет, Ctrl-r повторяет отменённое. /main ищет текст, n повторяет поиск. :set number включает номера, :set expandtab shiftwidth=4 softtabstop=4 задаёт отступы. :%s/old/new/g заменяет все совпадения; добавьте c в конце для подтверждения каждой замены. Освойте :help и пройдите vimtutor.

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
        System.err.println("diagnostic");
    }
}
```

```bash
javac -encoding UTF-8 -d out src/Hello.java
java -cp out Hello > result.txt 2> error.txt

```

println добавляет перевод строки. Первый вызов пишет в stdout, второй в stderr. Перенаправление > создаёт или перезаписывает файл, 2> перенаправляет дескриптор 2. Конвейер | соединяет stdout одного процесса со stdin следующего; stderr автоматически в него не попадает.

## Занятие 2. Компиляция и модель JVM

javac проверяет синтаксис, типы, доступность имён и создаёт class-файлы. JVM загружает классы, проверяет байткод и исполняет его; реализация может интерпретировать методы и компилировать горячие участки в машинные инструкции. class-файл не является машинным кодом конкретного процессора. Переносимость ограничена версией формата, доступными API и платформенными зависимостями.

JDK содержит инструменты разработки и среду исполнения. JVM - виртуальная машина, а не синоним всего JDK. Java автоматически управляет памятью объектов, но не закрывает произвольные файловые дескрипторы по окончании области видимости. Устройство сборщика мусора не следует выводить из поведения одной маленькой программы.

```bash

```

```java
package course;
public class Main {
    public static void main(String[] args) {
        int x = 7;
        System.out.println(x * 6);
    }
}
```

```bash

  -d out src/course/Main.java

javap -classpath out -c -l -p course.Main
javap -classpath out -verbose course.Main
```

Имя запуска course.Main - двоичное имя класса, не путь к исходнику. Корень classpath out должен содержать каталог course. Опция -d создаёт структуру пакетов. --release 21 ограничивает язык, формат class и доступные API целевой платформой; это надёжнее одной пары -source/-target. -g добавляет сведения для отладки. -Xlint:all включает дополнительные предупреждения, но не доказывает корректность.

В байткоде метода main найдите загрузку констант, сохранение локальной переменной и вызов println. imul потребляет два int со стека операндов и оставляет произведение. Локальные переменные кадра метода и стек операндов - части абстрактной JVM, не прямое описание регистров процессора. Таблица номеров строк связывает инструкции с исходником; -g помогает отладчику показывать локальные имена.

ClassNotFoundException при запуске обычно указывает на имя или classpath; ошибка компиляции cannot find symbol возникает раньше. UnsupportedClassVersionError означает, что среда исполнения не понимает версию class-файла. NoSuchMethodError может появиться при несовместимых версиях классов: успешная компиляция не гарантирует согласованность библиотек при запуске.

## Занятие 3. Целые числа и биты

byte, short, int, long - знаковые целые шириной 8, 16, 32, 64 бита. Для n бит диапазон равен [-2^(n-1), 2^(n-1)-1]. char - беззнаковая 16-битная кодовая единица UTF-16. boolean не является целым числом. В отличие от Python, int не растёт автоматически. Операции int выполняются с отбрасыванием старших битов: переполнение обычного сложения не вызывает исключения.

Большинство арифметических операций над byte и short сначала продвигает операнды до int. Присваивание byte c = a + b не компилируется без приведения; c += b содержит неявное сужение. Приведение (long)(a * b) слишком поздно, если оба операнда int: переполнение уже произошло. Нужно (long)a * b. Для операций с обязательной проверкой границ используйте Math.addExact и Math.multiplyExact.

```java
public class IntegerLab {
    public static void main(String[] args) {
        int a = 50_000;
        System.out.println(a * a);
        System.out.println((long) a * a);
        System.out.println(-7 / 3);
        System.out.println(-7 % 3);
        System.out.println(-1 >>> 1);
    }
}
```

Вывод: -1794967296, 2500000000, -2, -1, 2147483647. Деление целых округляет к нулю. Остаток имеет знак делимого или равен нулю; при ненулевом b верно a = (a / b) * b + a % b в арифметике типа. Деление на ноль бросает ArithmeticException. Особый случай MIN_VALUE / -1 возвращает MIN_VALUE из-за переполнения.

Дополнительный код удобен тем, что одно двоичное сложение работает для положительных и отрицательных значений. Отрицание x эквивалентно ~x + 1 по модулю 2^n. Поэтому у MIN_VALUE нет положительного аналога того же типа, а Math.abs(MIN_VALUE) остаётся отрицательным. Это контрпример к наивной реализации алгоритма Евклида через abs(int).

Операторы & | ^ ~ работают по битам; && и || работают с boolean и сокращённым вычислением. >> распространяет знаковый бит, >>> заполняет нулями. Для int расстояние сдвига маскируется до 5 младших битов: 1 << 32 равно 1, а не 0. Для long используются 6 бит. Проверка одного бита: (x & (1 << k)) != 0 при заранее проверенном k от 0 до 31.


## Разбор алгоритма Евклида

```java
public class Gcd {
    static long gcd(int x, int y) {
        long a = Math.abs((long) x);
        long b = Math.abs((long) y);
        while (b != 0) {
            long r = a % b;
            a = b;
            b = r;
        }
        return a;
    }
    public static void main(String[] args) {
        System.out.println(gcd(Integer.MIN_VALUE, 0));
        System.out.println(gcd(48, 18));
    }
}
```

Получаем 2147483648 и 6. Приведение к long предшествует abs. Инвариант: множество общих делителей a и b сохраняется при переходе (a,b) -> (b,a%b). При b > 0 остаток строго меньше b, поэтому неотрицательная целочисленная мера убывает и цикл завершается. В конце gcd(a,0)=a. По контракту gcd(0,0)=0; это программное соглашение. В модели арифметических шагов число итераций O(log max(a,b)); стоимость деления больших чисел требует отдельной модели.

## Занятие 4. Методы, значения и ссылки

Java всегда передаёт аргументы по значению. Для примитива копируется само значение; для объекта копируется значение ссылки. Метод может изменить доступный через ссылку массив, но присваивание параметру новой ссылки не меняет переменную вызывающего метода. Аналогия с C++: параметр Java не становится T&. Аналогия с Python полезна для совместного доступа к объекту, но не заменяет статическую систему типов Java.

```java
public class References {
    static void change(int[] a) {
        a[0] = 9;
        a = new int[] {100};
    }
    static int lowerBound(int[] a, int key) {
        int left = 0, right = a.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (a[mid] < key) left = mid + 1;
            else right = mid;
        }
        return left;
    }
    public static void main(String[] args) {
        int[] values = {1, 3, 3, 8};
        System.out.println(lowerBound(values, 3));
        change(values);
        System.out.println(values[0]);
    }
}
```

Вывод 1 и 9. После change массив уже не отсортирован, поэтому повторный бинарный поиск нарушил бы предусловие. Переназначение a создало новый массив и изменило только локальный параметр. Ссылки сравниваются == по идентичности; содержимое массивов сравнивают Arrays.equals. null означает отсутствие ссылки; обращение к элементу через null приводит к NullPointerException.

Массив имеет фиксированную длину. new int[n] заполняет элементы нулями, массив ссылочного типа - null. Локальная переменная сама по себе не получает автоматически допустимое значение для чтения: компилятор требует definite assignment. Индексы от 0 включительно до length исключительно. Двумерный int[][] является массивом ссылок на массивы, строки могут иметь разную длину.


## Доказательство lowerBound

Контракт: входной массив отсортирован неубывающе; результат - первый индекс i с a[i] >= key, либо length. Инвариант: 0 <= left <= right <= n, все элементы до left меньше key, все элементы начиная с right не меньше key. Изначально обе зоны пусты. Если a[mid] < key, вся левая часть до mid включительно исключается по сортировке. Иначе mid остаётся кандидатом, поэтому right=mid. Мера right-left строго уменьшается. При равенстве границ зоны встречаются в искомой позиции.

Формула mid избегает переполнения left+right при допустимых индексах. Алгоритм требует O(log n) сравнений и O(1) дополнительной памяти. Но проверка сортировки перед каждым запросом стоит O(n); это часть контракта, а не бесплатная операция. Рекурсивный вариант использовал бы O(log n) кадров стека.

## Занятие 5. Вещественные числа и текст

double хранит приближение в двоичной системе IEEE 754. Многие десятичные дроби, включая 0.1, не представимы точно. Величина ошибки зависит от масштаба: расстояние между соседними представимыми числами меняется с порядком. Равенство double проверяет равенство представленных значений, а не математических выражений. Вычитание близких приближений может уничтожить значащие цифры.

```java
public class Floating {
    static boolean close(double a, double b,
                         double abs, double rel) {
        if (abs < 0 || rel < 0 ||
            !Double.isFinite(abs) || !Double.isFinite(rel)) {
            throw new IllegalArgumentException("tolerance");
        }
        if (a == b) return true;
        if (!Double.isFinite(a) || !Double.isFinite(b)) return false;
        return Math.abs(a - b) <= Math.max(abs,
            rel * Math.max(Math.abs(a), Math.abs(b)));
    }
    public static void main(String[] args) {
        System.out.println(0.1 + 0.2 == 0.3);
        System.out.println(close(0.1 + 0.2, 0.3, 1e-15, 1e-12));
        System.out.println(Double.NaN == Double.NaN);
    }
}
```

Вывод false, true, false. Абсолютный допуск нужен около нуля, относительный - на больших масштабах. Допуски выводятся из требований задачи, а не выбираются по привычке. Пример close ориентирован на умеренные масштабы: разность и произведение rel*scale тоже могут переполниться при экстремальных конечных значениях. Приближённое равенство нетранзитивно и не подходит для equals ключей коллекции.

Деление double на ноль даёт бесконечность или NaN, а не целочисленное ArithmeticException. NaN не равен самому себе, используйте Double.isNaN. Денежная десятичная арифметика обычно требует BigDecimal из строки, например new BigDecimal("0.1"); конструктор из double переносит двоичную погрешность. Деление BigDecimal может потребовать явной точности и режима округления.


## Бисекция как численная лабораторная

Для непрерывной функции f на [a,b] с противоположными знаками на концах теорема о промежуточном значении гарантирует корень. На каждом шаге выбирают половину с изменением знака. После k шагов длина интервала равна исходной длине / 2^k; для ошибки середины не более eps достаточно длины <= 2*eps. Условие малого |f(x)| само по себе не гарантирует малой ошибки x, если производная близка к нулю.

В машинной арифметике середина может совпасть с одним из концов: дальнейшее сужение невозможно. Поэтому реализация обязана иметь лимит итераций, проверку конечности значений и проверку mid==a или mid==b. Для ограниченного интервала [0,2] вычисляйте mid=a+(b-a)/2; для произвольных огромных концов отдельно анализируйте переполнение разности. Не проверяйте знак через f(a)*f(b): произведение может переполниться или округлиться к нулю.


## Строки: кодовые единицы и символы

String неизменяем. length() считает кодовые единицы UTF-16; символ вне BMP занимает пару surrogate. Для строки "A😀" length равно 3, а codePointCount(0,length) равно 2. И это ещё не число пользовательских графем: буква с комбинируемым акцентом может состоять из нескольких code point. charAt не обещает целый Unicode-символ. Для обхода кодовых точек используйте codePoints().

```java
String s = "A😀";
System.out.println(s.length());
System.out.println(s.codePointCount(0, s.length()));
s.codePoints().forEach(System.out::println);
```

Строки сравнивают equals; == проверяет идентичность объектов и может обманчиво работать для интернированных литералов. Конкатенация в цикле создаёт промежуточные строки; для накопления используйте StringBuilder. Кодировка файла UTF-8 и внутреннее представление текста на уровне API - разные вопросы. Явное -encoding UTF-8 устраняет зависимость компилятора от настроек среды.

## Занятие 6. Классы и контракты

Класс связывает состояние и допустимые операции. Инвариант - свойство каждого корректного наблюдаемого состояния. Конструктор устанавливает инвариант; каждый открытый метод обязан его сохранять. private ограничивает доступ к представлению. final у поля запрещает переназначение, но не делает объект по ссылке неизменяемым. Для изменяемых массивов нужна защитная копия при приёме и выдаче.

```java
public final class Fraction {
    private final long numerator;
    private final long denominator;

    public Fraction(int n, int d) {
        if (d == 0) throw new IllegalArgumentException("zero denominator");
        long a = n, b = d;
        if (b < 0) { a = -a; b = -b; }
        long x = Math.abs(a), y = b;
        while (y != 0) {
            long r = x % y;
            x = y; y = r;
        }
        numerator = a / x;
        denominator = b / x;
    }
    public long numerator() { return numerator; }
    public long denominator() { return denominator; }
    @Override public String toString() {
        return numerator + "/" + denominator;
    }
    public static void main(String[] args) {
        System.out.println(new Fraction(6, -8));
        System.out.println(new Fraction(0, -5));
    }
}
```

Вывод -3/4 и 0/1. Инварианты: знаменатель положителен, gcd(|n|,d)=1, ноль представлен как 0/1. Вход ограничен int, поэтому временные long безопасно вмещают отрицание MIN_VALUE. Перенос конструктора на long без пересмотра доказательства нарушит безопасность abs и отрицания. Поля final и отсутствие мутаций делают этот объект неизменяемым на уровне его состояния.

Исключение разрывает обычное выполнение и передаёт управление ближайшему подходящему catch. IllegalArgumentException сообщает о нарушении контракта вызывающим кодом. IOException - проверяемое исключение: его нужно обработать или объявить throws. Не ловите Exception только ради продолжения после неизвестной ошибки. На границе CLI ожидаемую ошибку ввода следует превратить в понятное сообщение stderr и ненулевой код завершения.

equals должен быть рефлексивным, симметричным, транзитивным и согласованным; для null возвращать false. Равные объекты обязаны иметь одинаковый hashCode. Fraction пока наследует идентичность Object: две равные математические дроби не равны через equals. Это осознанное ограничение примера, которое предстоит исправить в задании. toString отвечает за представление, а не за равенство.

## Занятие 7. Проверки и отладчик

Тест - исполняемая проверка конкретного свойства, а не доказательство для всех входов. Разделяйте примерные тесты, граничные случаи и свойства. Для gcd полезны симметрия, неотрицательность и делимость исходных значений результатом при ненулевом результате. Свойство gcd(a,b)<=min(abs(a),abs(b)) неверно при одном нулевом аргументе: даже тестовое свойство нуждается в предусловии.

Встроенный assert отключён по умолчанию и включается java -ea. Он подходит для внутренних предположений, но не заменяет проверку входа публичного метода. Для учебных обязательных тестов используйте явное выбрасывание AssertionError: тогда забытый -ea не превращает красный тест в зелёный.

```java
public class Checks {
    static void equal(long expected, long actual) {
        if (expected != actual) {
            throw new AssertionError("expected=" + expected
                + ", actual=" + actual);
        }
    }
    public static void main(String[] args) {
        equal(6, Gcd.gcd(48, 18));
        equal(0, Gcd.gcd(0, 0));
        equal(2147483648L, Gcd.gcd(Integer.MIN_VALUE, 0));
        System.out.println("OK: 3 checks");
    }
}
```

```bash

```

## Занятие 8. Упаковка и воспроизводимость

JAR - архив с классами и ресурсами. Исполняемый JAR содержит атрибут Main-Class в манифесте; это не превращает архив в независимый от JVM бинарный файл. classpath нужен и при компиляции зависимых классов, и при запуске. Для Linux разделитель нескольких корней :; для Windows ;. В этом учебнике все команды рассчитаны на Linux.

```bash
javac --release 21 -encoding UTF-8 -g -d out src/course/Main.java
jar --create --file module1.jar --main-class course.Main -C out .
jar --list --file module1.jar
java -jar module1.jar
java -cp module1.jar course.Main
```

-C out . добавляет содержимое out в корень архива. Если добавить сам каталог out, ожидаемая структура course/Main.class окажется вложена на лишний уровень. java -jar использует сведения архива; не рассчитывайте, что обычный -cp будет определять его зависимости. В рамках модуля архив самодостаточен относительно ваших классов и требует установленной совместимой JVM.

S4. Исследуйте численную устойчивость корней квадратного уравнения: подберите коэффициенты с потерей точности, выведите устойчивую формулу и сравните с высокоточным эталоном. Эта задача дополнительная и не заменяет обязательную лабораторную.
